# 部署与运维手册

## 1. 环境要求

| 组件 | 版本 | 说明 |
|------|------|------|
| Python | 3.12 | 后端运行时 |
| MySQL | 8.0.x | 业务库 `db_runner`（Django 5.2 LTS 兼容 8.0；若用 Django 6 需 MySQL 8.4+） |
| Node.js | ≥ 18（实测 24） | 管理端与小程序构建 |
| 缓存 | Django 缓存框架 | **默认 DatabaseCache，无需 Redis**；如需 Redis 可改 `CACHES` |
| 微信开发者工具 / HBuilderX | 最新 | 小程序真机或 H5 演示（可选） |

> 与计划书的差异：计划书写 Redis + Celery，实际交付用 **Django DatabaseCache（锁/限流/规则缓存）+ `manage.py beat` 循环**，
> 依赖更少、演示环境零额外中间件；二者接口等价，替换只需改 `settings.CACHES` 与任务守护方式。

## 2. 环境变量（`backend/.env`）

```ini
DJANGO_SECRET_KEY=<48 位随机串，禁止入库/Git>
DJANGO_DEBUG=false
DJANGO_ALLOWED_HOSTS=example.edu.cn,127.0.0.1
DB_ENGINE=mysql            # sqlite 可作临时演示
DB_NAME=db_runner
DB_USER=runner_app
DB_PASSWORD=<强口令>
DB_HOST=127.0.0.1
DB_PORT=3306
CACHE_BACKEND=db           # db=DatabaseCache（多进程互斥）；mem=单进程内存缓存
ACCESS_TOKEN_MINUTES=30
REFRESH_TOKEN_DAYS=7
```

生成密钥：`python -c "import secrets;print(secrets.token_urlsafe(48))"`。
分 dev / test / prod 三套 `.env`，生产环境用 systemd `EnvironmentFile` 或容器 Secret 注入。

## 3. 首次部署

```bash
# 1) 数据库与账号（最小权限：仅 db_runner 的 CRUD + 索引）
mysql -uroot -p <<'SQL'
CREATE DATABASE db_runner DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'runner_app'@'127.0.0.1' IDENTIFIED BY '<强口令>';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,INDEX,REFERENCES ON db_runner.* TO 'runner_app'@'127.0.0.1';
FLUSH PRIVILEGES;
SQL

# 2) 代码与依赖
git clone <repo> && cd <repo>
python -m venv .venv && .venv/bin/pip install -r backend/requirements.txt

# 3) 建表与缓存表
cd backend
../.venv/bin/python manage.py migrate --fake-initial
../.venv/bin/python manage.py createcachetable
../.venv/bin/python manage.py collectstatic --noinput

# 4) 管理员与演示数据（生产可只建管理员）
../.venv/bin/python manage.py seed_demo
DJANGO_SUPERUSER_PASSWORD=... ../.venv/bin/python manage.py createsuperuser

# 5) 管理端构建
cd ../admin-web && npm ci && npm run build     # dist/ 交给 Nginx
```

## 4. 进程守护（systemd 示例，Linux）

```ini
# /etc/systemd/system/runner-api.service
[Unit]
Description=Runner API (Gunicorn)
After=network.target mysql.service

[Service]
WorkingDirectory=/srv/runner/backend
EnvironmentFile=/srv/runner/backend/.env
ExecStart=/srv/runner/.venv/bin/gunicorn config.wsgi:application -w 4 -k gthread --threads 4 -b 127.0.0.1:8000 --access-logfile - --error-logfile -
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/runner-beat.service   定时任务循环（替代 Celery beat）
[Service]
WorkingDirectory=/srv/runner/backend
EnvironmentFile=/srv/runner/backend/.env
ExecStart=/srv/runner/.venv/bin/python manage.py beat
Restart=always
User=www-data
```

> 也可不用常驻进程，改用 crontab 每分钟调用 `manage.py run_tasks`，每日 03:00 调用
> `manage.py run_tasks --daily`（含信用恢复、托管告警、对账）。

## 5. Nginx（静态 + 反代）

```nginx
server {
    listen 443 ssl;
    server_name runner.example.edu.cn;
    ssl_certificate     /etc/ssl/runner.crt;
    ssl_certificate_key /etc/ssl/runner.key;

    root /srv/runner/admin-web/dist;         # 管理端静态
    location / { try_files $uri $uri/ /index.html; }

    location /api/ { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host;
                     proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                     proxy_set_header X-Forwarded-Proto $scheme; }

    location /static/ { alias /srv/runner/backend/staticfiles/; }

    # 上传目录禁止直接访问与执行（凭证走鉴权接口 /api/v1/files/<id>）
    location /media/ { deny all; }
    client_max_body_size 3m;
}
```

## 6. 备份与恢复

```bash
# 每日全量（保留 7 天）
mysqldump -uroot -p --single-transaction --routines db_runner | gzip > /backup/db_$(date +%F).sql.gz
tar -czf /backup/uploads_$(date +%F).tar.gz -C backend media uploads
find /backup -type f -mtime +7 -delete

# 恢复
gunzip -c /backup/db_2026-01-01.sql.gz | mysql -uroot -p db_runner
```

## 7. 监控与告警

- 应用日志：Gunicorn/Django 分级输出；管理员操作、任务失败、对账结果全部落**操作日志表**（管理端「公告与日志」可查、可导出 CSV）
- 关键告警（生成 super_admin 通知）：
  - 对账不一致（3 条恒等式任一失败）
  - 订单异常（无送达凭证超时）与托管/申诉超期（默认 7 天）
- 健康检查：`GET /api/v1/announcements`（免业务数据的轻量接口）或自建 `/healthz` 反代探针

## 8. 常见故障排查

| 现象 | 排查 |
|------|------|
| 启动报 `Did you install mysqlclient?` | 未引入 `config/__init__.py`（pymysql 适配）；确认以 `backend/` 为工作目录启动 |
| 报 `MySQL 8.4 or later is required` | Django 版本过高，回退 `Django==5.2.*` |
| 缓存相关报错 `Table 'cache_table' doesn't exist` | 执行 `manage.py createcachetable`（测试环境自动用内存缓存） |
| 登录总提示「密码错误」 | 演示账号密码见 README；密码策略要求 ≥8 位含字母数字 |
| 前端 401 循环 | access 过期且 refresh 被拉黑（改密/封禁）；重新登录 |
| 定时任务不执行 | 确认 `runner-beat` 在跑或 crontab 已配；`manage.py run_tasks --daily` 手工触发验证 |
| 提现审核后余额异常 | 执行 `manage.py run_tasks --only reconcile` 校验三恒等式 |
| 上传报「文件内容与图片格式不符」 | 上传的是伪改扩展名文件；仅支持真实 jpg/png ≤2MB |

## 9. 发布与回滚

1. 迁移可回退：`manage.py migrate <app> <前一版本号>`；上线前 `migrate --fake-initial` 校验
2. 发布顺序：备份 → 停 beat → 迁移 → 重启 API → 启 beat → 冒烟 `scripts/smoke_api.py`
3. 失败回滚：`git checkout <上一 tag>` → 回退迁移 → 重启 → 复核资金对账
